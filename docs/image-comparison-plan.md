# 选图对比台：产品与实现方案

状态：2026-09-28 已实现首版，随后根据用户截图反馈改为独立全屏页，增加左侧全部图片列表、底部双操作卡片及对话入口。当前实现与验证记录见 [选图对比](image-comparison.md)。以下保留最初批准方案，原弹窗、固定成员和仅图库入口设计已被后续版本替代。

## 1. 推荐方案

在「我的图片」现有批量管理工具栏中增加「对比」，选择 2～4 张图片后打开覆盖工作区的对比界面。支持同步缩放和平移、独立查看、收藏、下载、查看提示词和继续编辑。

首版的完整流程：选图 → 比较整体 → 放大检查细节 → 收藏满意图片 → 下载或继续编辑。首版沿用现有收藏，不引入全局「采用／淘汰」状态：同一张图可能在不同项目中具有不同结论，正式定稿应在未来项目上下文中定义。

适用对象：当前用户已保存的生成图和编辑结果，允许来自不同聊天、不同生成批次。

## 2. 解决的问题和成功标准

- 用户不必在多张图之间反复打开、关闭编辑器来比较构图、文字和细节。
- 比较时保持相近的观察位置，减少逐张拖动和缩放。
- 选图结果通过已有收藏保存，回到图库后立即可见。
- 比较过程中随时能对指定图片继续编辑，不重新上传或丢失来源。
- 大图库依然按需分页；打开对比只读取所选图片，最多 4 张详情。

验收主要看真实任务：从同一批 4 张结果中选择满意图并开始续改，过程中无需依次打开 4 个编辑器；关闭对比后不丢当前图库位置和原批量选择。

## 3. 首版入口与选图规则

### 3.1 主入口

「我的图片」→「批量管理」→勾选图片→「对比」。

工具栏在收藏操作前增加对比按钮，沿用现有按钮、图标、禁用样式和居中 toast。普通模式下点击图片仍进入现有编辑器。

| 已选数量 | 对比入口 |
| --- | --- |
| 0～1 张 | 禁用，并可见提示「请选择 2～4 张图片进行对比」 |
| 2～4 张 | 可用，显示「对比（N）」 |
| 5～200 张 | 禁用，提示「一次最多对比 4 张，请减少选择」 |

保留现有批量管理 200 张上限及其他批量操作限制，不自动截取前 4 张、不自动改动用户选择。批量收藏、下载等操作正在提交时，沿用工具栏互斥规则。

### 3.2 对比成员

- 按勾选顺序产生 A、B、C、D 编号；打开时冻结 ID 顺序，不随图库排序、分页和收藏筛选变化。
- 相同 ID 去重；不同 ID 即使画面相同也允许比较。
- 首版不在对比界面另做图库选择器。用「返回选图」关闭覆盖层，在原批量选择上调整后重新对比。
- 对比内不提供删除图片、自动淘汰、替换图片或拖动重排，避免增加操作分支。
- 首版不增加侧栏菜单、公开地址或分享链接。

## 4. 界面布局

桌面采用近全屏覆盖层，为图片保留最大空间；底层图库保持挂载并锁定滚动。图片区域使用统一中性背景，透明图片沿用棋盘格。

```text
┌ 选图对比 · 4 张                         返回选图 ┐
│ 同步查看 [开]   适应   1:1   −  倍率  +   信息 │
├──────────────────────┬───────────────────────┤
│ A · 1024×1024    收藏 │ B · 1024×1024    收藏 │
│                      │                       │
│        图片 A        │        图片 B         │
│                      │                       │
├──────────────────────┼───────────────────────┤
│ C · 1024×1024    收藏 │ D · 1024×1024    收藏 │
│                      │                       │
│        图片 C        │        图片 D         │
│                      │                       │
├──────────────────────┴───────────────────────┤
│ 当前图片 B                    下载   继续编辑 │
└──────────────────────────────────────────────┘
```

### 4.1 排布

- 桌面宽度 ≥ 1200px：2 张双列；3 张三列；4 张 2×2。
- 768～1199px：2 张双列；3～4 张 2×2，3 张时空位保持留白，不增加无关卡片。
- < 768px：固定上下两个观察窗，先展示 A、B；3～4 张时，下方编号缩略条允许把 C、D 切入当前观察窗。两个窗不能指向同一图片。
- 屏幕旋转、窗口变化时保留成员和收藏，重算布局；适应模式重算 fit，放大模式保留观察中心并限制边界。
- 界面适配现有浅色／深色主题。触摸操作有足够点击区域，收藏不依赖 hover 才显示。

### 4.2 当前图片

点击图片或其编号成为「当前图片」，边框和文字共同标识，避免只靠颜色。默认 A。

「下载」「继续编辑」「查看信息」始终作用于当前图片；顶部倍率在独立模式下也作用于当前图片。点击每格自己的收藏按钮，仅操作该格，不隐式更换当前图片。

信息默认收起；展开后显示当前图片的完整用户提示词、实际尺寸、生成／编辑类型及时间，并支持复制提示词。不展示渠道密钥、账号标识或内部注入提示。当前 WorkImage 没有独立的实际模型字段，首版不猜测模型名称。

## 5. 同步查看与画质

### 5.1 默认行为

- 默认同步开启，所有图完整居中显示，保持原宽高比，不裁切、不拉伸。
- 在任意图片上开始拖动或缩放时，将其作为本次操作的基准图。
- 同步是「相同相对观察位置与放大程度」，不承诺识别主体或自动对齐人物／商品。
- 横图、竖图和不同构图的图可以比较；同步到边界时各格独立限制，空白区域不得无限拖出。

### 5.2 两种明确的比例语义

1. **适应视窗**：每张图按各自观察窗完整显示；后续放大采用相对适应尺寸的倍率。界面标示「适应倍率 1×／2×」，不能将这个 1×称为原图 100%。
2. **1:1**：以一个图像像素对应一个 CSS 像素查看，切换至原图资源；所有图采用相同绝对像素比例。界面标示「原图比例 100%」。高 DPI 屏幕按 CSS 像素定义，不宣称对应设备物理像素。

「适应」重置观察中心并返回适应模式。「1:1」以现有观察中心切换至原图比例。放大上限沿用预览现有 300% 原图尺度；同步时以所有可见图片的共同有效范围限制倍率，避免某格已达上限而其他图继续变大。

### 5.3 同步开关

- 关闭同步后，各图保留当前位置，可分别放大、拖动。
- 重新开启时，以当前图片的模式、倍率和归一化中心为基准同步其他图，不回到默认位置。
- 手势沿用用户的预览滚轮偏好；缩放模式下滚轮缩放，平移模式下滚轮平移，Ctrl／Meta + 滚轮缩放。画面内拖动平移，工具栏提供独立缩放按钮。
- 移动端支持双指缩放和拖动；在对比界面内不使用横滑切换图片，避免与平移冲突。

### 5.4 预览和原图

- 入场先用已有缩略图占位，每格独立读取预览；某一格加载慢不会阻塞其余格。
- 提供「预览／原图」画质切换；进入 1:1 或放大到预览像素不足时，加载原图。
- 原图下载／解码并发最多 2 张，先处理当前图片；移动端只加载正在显示的两个观察窗。
- 原图替换预览时按真实图片坐标保持位置和倍率，避免发生跳动。
- 加载期间显示「原图加载中」；失败显示「当前为预览图」和重试按钮，不能把低清预览标成原图已就绪。
- 首版不旋转、叠加差分或做擦除滑块，这些功能具有额外的对齐语义。

## 6. 收藏、下载和继续编辑

### 6.1 收藏

收藏沿用现有用户收藏关系，可收藏任意多张对比图。每格有明确的未收藏／已收藏状态；仅当前提交中的按钮禁用，失败显示原因并恢复状态。

更新对比详情、图库卡片、收藏筛选数量等相关缓存。尤其在「仅收藏」图库中取消收藏时，图片仍留在本次对比里；关闭后图库按真实收藏状态更新，不导致对比成员突然减少。

### 6.2 下载

底部「下载」下载当前图片，复用现有 ImageDownloadMenu 及原图／预览图／缩略图选项。批量 ZIP 继续使用图库原有批量下载流程，首版不在这里再加一套下载选择。

### 6.3 继续编辑

- 点击「继续编辑」前重新确保当前图片可访问，保存本轮对比草稿，然后沿用图片详情 → 编辑请求 → 工作台的既有链路。
- 编辑器显示本次对比中仍有效的图片，当前图片保持选中；不把全部图库或用户看不到的图片加入此次上下文。
- 打开编辑器不自动提交生图；生成结果不自动替换旧对比图。
- 回到「我的图片」可点击「继续对比（N）」恢复本轮。编辑结果加入对比仍经正常批量选图完成。
- 编辑后不新增跨页面强制返回按钮，避免和现有聊天／编辑器返回行为冲突。

## 7. 状态保存与边界

采用「一次临时对比草稿 + 现有收藏持久化」。每个账号在当前浏览器标签页只保留一轮草稿。

| 状态 | 存储方式 | 生命周期 |
| --- | --- | --- |
| 成员 ID、顺序、当前 ID、同步开关、查看模式和中心／倍率 | 内存 store + 账号隔离的 sessionStorage | 同标签页刷新、导航可恢复；退出／切换账号清除；关闭标签页不承诺恢复 |
| 图片详情和媒体 URL | 现有 Query 缓存／内存 | 恢复时重新按 ID 获取并鉴权，不写入草稿 |
| 收藏结果 | 现有服务端收藏关系 | 跨会话和设备可见 |
| 当前图库的批量勾选、滚动位置 | 原 ImagesPage 状态 | 仅打开／关闭覆盖层时保持 |

草稿只保存 ID 和视图参数，不保存图片二进制、提示词、账号凭据或大列表。storage 不可用／容量不足时退回内存，不阻止对比。读取时校验版本、数量、ID 去重和数值范围。

正常「返回选图」保留草稿和底层批量勾选。开启新一轮对比替换上一轮草稿；原批量勾选在用户主动退出批量模式时按现有规则清空。

恢复入口不依赖图片是否已经出现在图库当前页，直接按已保存的 2～4 个 ID 读取详情。对比草稿不跟随图库筛选结果自动裁减。

## 8. 异常、键盘和无障碍

- 某图已删除／无权访问：对应格显示「图片不可用」，不暴露具体归属；其他图正常可用。无效项不启用收藏、下载或编辑。
- 剩余至少 2 张时允许「移除不可用项」并继续；少于 2 张时展示返回选图入口，不伪装成有效对比。返回时保留仍有效 ID。
- 网络错误和暂时加载失败允许单格重试，不立即删除成员。整体请求失败也能关闭。
- 详情缺少真实尺寸时，先等媒体解码获取 naturalWidth／naturalHeight；确认前不启用原图 1:1。只把实际原图或可信原始元数据当作原始尺寸。
- 请求结果到达前已关闭／换轮：取消可取消的请求，并拒绝旧轮结果覆盖新轮状态。
- 用户退出登录／切换账号：关闭对比，清除旧账号草稿和私有缓存。
- 对比用语义化模态框，进入后焦点在内部，关闭后回到触发按钮。Tab 正常访问工具栏、图片选择按钮及操作按钮。
- Esc 仅关闭最上层弹层；对比打开时，底层批量模式 Esc 监听必须停用，防止按一次 Esc 同时清空选择。
- 非输入状态下支持 1～4 选中图片、F 收藏当前图、0 适应、+／−缩放；组合快捷键、输入框、文本选择和 IME 输入时不拦截。移动端同样有可见按钮。
- 重要反馈用现有 toast 和 aria-live，拖动每一帧不触发读屏播报；编号、标签和焦点样式共同表达状态。

### 9.2 建议模块

- ImageCompareDialog.tsx：模态层、成员加载、当前图片与操作编排。
- ImageCompareViewport.tsx：单格显示和手势，仅接受受控视图参数。
- useImageCompareViewport.ts：同步／独立视图状态和 resize 协调。
- imageCompare.ts：ID 校验、模式转换、倍率／中心／平移边界纯计算。
- 独立 comparison store：草稿恢复和账号生命周期，不把对比成员塞进图库 selectedImageIds。
- images-comparison.css：局部样式；现有所有启用语言补齐新增文案。

不直接挂载 4 个完整 ImagePreviewModal：其每个实例都有门户、全局事件、滚动锁和单图导航。复用展示控件或必要的纯计算，保持对比只有一个模态层和一套事件管理。

### 9.3 API 与数据库

首版预计不需要新增数据库表或后端接口：

- GET /api/images/:id：最多 4 个详情请求，使用独立 Query 和每格错误状态，不采用任一失败即整体失败的处理。
- PUT /api/images/:id/favorite：已有收藏写入，遵循现有鉴权与错误处理。
- 下载继续使用现有下载菜单与受保护媒体链路。
- 继续编辑使用现有编辑请求，CPA／ChatGPT Web／API 的选路和生图参数不发生变化。

API 是否完全覆盖所有失败状态，在实现前补查具体服务端分支；如确有缺口，单独说明后再扩大方案。当前方案不新增 studio_settings 或 provider_configs 配置项。

### 9.4 同步计算要点

fitScale = min(可用窗宽 / 原图宽, 可用窗高 / 原图高)。适应模式 scale_i = fitScale_i × sharedZoom；1:1 模式 scale_i = sharedPixelScale。

中心位置使用原始图片坐标归一化为 u、v（0～1），由各格尺寸转换成平移量并裁剪。图小于观察窗时居中；图大于观察窗时允许拖动至边缘。缩放围绕基准图的指针落点计算新中心，再同步到其他格。

指针事件到渲染使用 requestAnimationFrame 合并；只更新最多 4 个观察窗，不在拖动每帧写 storage、请求接口或让图库虚拟列表重新布局。交互结束时再保存草稿。

## 10. 验收清单

| 类别 | 必须覆盖 |
| --- | --- |
| 入口 | 0、1、2、3、4、5 张的按钮状态；不改变 200 张批量规则；原卡片点击行为保持 |
| 布局 | 两图、三图、四图；横竖混合、超长图、透明图；320／390／768／1024／1440px；浅深主题 |
| 细节 | 同步缩放／拖动、独立模式、重新同步、边界、窗口变化、适应与原图 1:1 区别 |
| 画质 | 预览先出、原图并发上限、切换不跳动、原图失败不误标成功、移动端只载可见原图 |
| 收藏 | 单格提交、失败恢复、图库和详情缓存一致、仅收藏筛选下取消后对比不跳图 |
| 导航 | Esc 只关最上层；返回图库保留位置与批量选择；编辑目标准确；恢复草稿可跨分页读取 |
| 异常 | 单图 404／无权限、网络错误、少于 2 张有效图、关闭后的迟到响应、账号切换、storage 不可用 |
| 可访问性 | 键盘焦点、快捷键不影响输入、触摸操作、标签和状态播报 |
| 性能 | 无全库加载、无新增后台轮询、无生成调用；交互不触发网络请求或图库重排 |

实现后的验证包括几何和草稿纯函数边界测试、关键交互浏览器验证、bun run check、bun run build、git diff --check。生图渠道没有改动时，无需为验收对比界面发起收费生图；使用已有授权图片完成界面验证。

## 11. 实施顺序和后续扩展

1. 完成对比几何模型、模态层和 2／3／4 图布局，验证混合尺寸。
2. 接入批量入口、详情、同步交互、预览／原图加载。
3. 接入收藏、下载、继续编辑和草稿恢复，处理底层 Esc 与缓存变化。
4. 补齐移动布局、所有启用语言、无障碍与异常验证，更新帮助和功能文档。

四步共同构成可交付首版；同步几何、移动手势和原图资源管理是主要复杂点，不能只按「新增一个弹窗」估算。

后续可独立扩展：聊天图片组「本组对比」入口；固定 A 图逐张挑选的候选池；同尺寸编辑前后滑块；项目内的采用／淘汰与定稿；团队评审。它们不作为首版完成条件。
