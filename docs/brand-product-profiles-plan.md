# 品牌／商品档案：产品方案

状态：待评审方案，2026-09-29。本文描述拟新增能力，不代表已经实现；本轮只新增方案文档和对话内交互示意。

## 1. 产品定位

让用户一次整理品牌规则、商品事实和参考图片，之后选中档案即可开始创作，减少重复上传、重复描述和不同人员之间的风格偏差。

首版完成这条流程：建立档案 → 在对话中选用 → 查看本次带入的要求和参考图 → 生成／修改 → 按商品找回作品 → 继续复用。

面向当前图片工作台的创作需求，商品字段围绕外观、规格、卖点、参考图设计。库存、订单、价格同步、采购等经营管理不属于这一模块。

### 与已有功能的分工

| 功能 | 负责什么 | 与档案的关系 |
| --- | --- | --- |
| 素材库 | 存放、共享、引用图片文件 | 档案引用素材，并补充用途、顺序和使用规则 |
| 提示词表单 | 把某类创作任务组织成可填写的表单 | 档案提供重复使用的事实；表单提供本次任务结构 |
| 灵感空间 | 展示可以参考和复用的创作案例 | 从优质案例中挑选档案风格示例，需用户主动指定 |
| 我的图片／对比 | 浏览、比较、收藏、下载和继续编辑 | 新增按档案找回作品；沿用现有图片操作 |
| 品牌／商品档案 | 保存创作对象及其长期要求 | 将文字规则、商品信息和图片关联起来 |

## 2. 信息结构

品牌和商品采用两个独立实体。一个品牌可以关联多个商品，一个商品首版最多关联一个品牌；商品可以暂不归属品牌，适合代运营客户、白牌产品和临时任务。

首版一次创作选择一个品牌、一个商品及其一个规格。只选品牌也能创作；多商品合照、联名和套装留待后续扩展。

### 2.1 品牌档案

| 信息组 | 主要内容 | 如何参与创作 |
| --- | --- | --- |
| 基础资料 | 名称、简介、行业、目标人群、定位 | 提供背景，按本次任务选择带入 |
| 视觉规范 | Logo 主版本／反白版本、主色／辅助色、字体说明、常用风格 | 带入视觉方向和选中的 Logo 素材 |
| 表达规范 | 品牌口吻、固定名称、常用标语、禁用词／表达 | 作为文字生成和画面文案的要求 |
| 使用约束 | Logo 不拉伸、不变色、留白要求、避免的构图 | 默认启用，可查看具体内容 |
| 参考示例 | 推荐案例、反面示例及原因 | 正面示例可选为参考图；反面示例首版仅保留说明 |

创建时只必填品牌名称，其余可逐步补齐。颜色保存准确色值；字体首版记录名称和排版意图，字体文件管理及可编辑文字排版放到后续。

品牌资料的描述和视觉规则分开，避免一篇很长的品牌介绍被每次完整发送。

### 2.2 商品档案

| 信息组 | 主要内容 | 如何参与创作 |
| --- | --- | --- |
| 基本信息 | 商品名称、所属品牌、品类、型号／内部编码 | 明确本次创作对象，支持查找 |
| 规格 | 颜色、容量、尺寸、材质、包装版本 | 先确定本次选中的规格，避免混用不同版本 |
| 外观特征 | 轮廓、比例、结构、接口／按钮、Logo 位置 | 形成需要保留的外观要求 |
| 卖点与用途 | 用户确认的卖点、适用人群、使用场景 | 按任务选择使用，避免一次塞入所有卖点 |
| 参考图片 | 主图、正面、侧面、背面、细节、包装、场景 | 每张图有用途和所属规格，可设置默认引用 |
| 创作约束 | 不改颜色、不改变数量／结构、不增加不存在的配件等 | 默认带入，允许本次显式调整并留记录 |

最小可用档案：商品名称 + 一张已确认的商品主图。允许仅有名称的草稿，创作时提示补充图片会更有利于外观一致性。

规格采用轻量结构：用户可增加“奶油白／500 ml”“浅绿色／500 ml”等选项，并分别绑定参考图。基础事实由商品继承，同字段规格值优先；不搭建完整 SKU 经营系统。

AI 辅助识图提取放到第二阶段。AI 给出的材质、性能、容量等必须标为待确认建议；未经确认的卖点不自动作为商品事实进入生成要求。

## 3. 页面与入口

### 3.1 档案中心

侧边栏新增一个「品牌与商品」入口，页面内用「品牌」「商品」两个标签切换，避免新增两个一级导航。

支持按名称、商品编码搜索，以及按所属品牌、我的／站内共享、启用／已归档筛选。商品页默认全部商品，不要求先进入品牌。卡片展示主图、名称、所属品牌和规格，主要操作为「查看档案」「开始创作」。

### 3.2 详情页

- 品牌：概览、视觉规范、参考素材、关联商品。
- 商品：概览、规格与素材、创作要求、相关作品。
- 顶部保留「开始创作」，编辑入口使用现有项目样式。
- 商品切换规格时，同时切换有效参数和默认参考图；不混入其他颜色、型号的图。
- 相关作品首版展示当前用户有权访问的结果，默认是自己的作品，不自动公开其他成员的聊天或生成结果。

新增和编辑使用现有自定义表单、选择器、弹窗与居中 toast，详情采用正常页面；窄屏转为单列。

### 3.3 对话输入区

输入工具增加「选择档案」。选商品后，自动带出所属品牌及默认规格，输入框上方显示：

`品牌：山野日常 ×`　`商品：通勤保温杯 · 浅绿／500 ml ×`　`本次引用：3 张`　`查看要求`

标签展示当前上下文，用户仍只需填写“这一次要做什么”。「查看要求」展开本次有效规则、商品参数、已选卖点及参考图角色，可临时取消柔性风格或增减参考图。

选择档案或修改档案不会自动发起生成。与既有会话冲突的商品切换应给出明确提示，建议开启新对话；不能只换前端标签而继续沿用旧商品的上游上下文。

### 3.4 从已有素材建立档案

素材库图片的更多菜单提供「加入档案」，可选择现有品牌／商品，或以当前图片快速新建商品。档案直接引用现有素材，不重复上传；图片删除前要能看到档案引用情况。

生成结果通过主动「加入档案参考」沉淀为示例。生成图默认归入作品历史，不自动成为真实商品外观依据。

## 4. 一次完整的使用流程

以虚构品牌“山野日常”的 500 ml 通勤保温杯为例，示例规格和卖点均用于方案演示。

1. 创建品牌，录入自然、克制的视觉方向和 Logo 使用规则。
2. 创建商品，录入浅绿色、500 ml、圆柱杯身等已确认资料，关联正面、侧面和细节图。
3. 点击「开始创作」，对话带入品牌、商品、规格，展示本次引用的三张图。
4. 输入“做一张秋季通勤场景图，放在办公桌上，右侧留出标题位置”。
5. 查看本次要求：商品外观和结构需要保留；品牌风格为默认方向；秋季办公桌和标题留白为本次要求。
6. 提交后沿用当前生图／改图任务流程。结果可以对比、收藏、下载、继续编辑。
7. 后续从该商品的「相关作品」找回这张图，再做新的场景；只有主动加入档案参考的结果才会成为可复用示例。

## 5. 本次创作如何组合资料

### 5.1 用户能看见的组合方式

本次要求 = 选中的商品事实与规格 + 启用的品牌／商品规则 + 本次任务描述 + 已确认的参考图片。

保存两个不同概念：用户输入的原文、实际组装后的生成内容。输入框不被大量档案文字占满；任务详情可展开查看实际采用了哪些内容。

| 内容 | 首版处理规则 |
| --- | --- |
| 商品事实 | 采用选中规格的确定值；不从其他规格或参考场景里推测 |
| 外观保留要求 | 默认启用；解除或临时修改必须显式操作，只影响本次 |
| 品牌柔性风格 | 作为默认值，本次创作可覆盖，例如从浅色切换为暗背景 |
| 提示词表单 | 填入本次任务信息，可引用档案字段，不重复拼接同一段规则 |
| 参考图 | 明确区分商品外观、Logo、风格、构图，各有用途说明和顺序 |

结构化选择器中能确定的矛盾直接提示，例如不同颜色规格、品牌不匹配。自由文本的语义冲突首版不承诺全面自动识别；用户可在提交前检查汇总。以后可增加 AI 提醒，但不能悄悄修改用户意图。

“需要保留”是给模型的明确要求，不是像素级锁定能力。产品界面不承诺商品绝对不变形、Logo 完全准确、文字百分百正确。严格 Logo 和文案需要后续的确定性叠加排版；首版通过参考图和现有对比功能人工检查。

### 5.2 参考图选取

- 档案可保存多张图，默认只引用商品主图与关键辅助图，建议先选 1～3 张；实际数量按渠道能力校验。
- Logo 不默认加入所有商品场景，用户需要其出现在画面中时再选，避免额外 Logo 干扰包装上的标志。
- 风格示例必须标注“仅参考风格”，避免模型将示例里的另一款商品当成创作对象。
- 切换规格后清理不匹配的参考图；更换档案时只移除档案自动带入的条目，保留用户手动添加项，并显示变化。
- 超出渠道支持范围时要求调整或切换可用渠道，不静默截断；不支持参考图的路径不能无提示降为纯文字。
- 首版由用户明确选择参考图片，不增加向量库或全库自动检索。

### 5.3 会话、编辑与历史

- 在当前会话保存档案选择，跨会话不自动继承，防止将客户 A 的资料带到客户 B。
- 提交时冻结档案版本、有效字段、规则、参考图身份／内容指纹和实际提示词。
- 自动重试、补图、服务恢复复用原任务快照；手动重试默认沿用原要求，采用最新档案则创建新任务。
- 档案更新只影响新的提交。草稿显示“档案已更新”，由用户决定是否刷新；不能改写历史任务。
- 继续编辑时带出原任务要求，并允许更新到当前档案。先校验档案及素材权限，再创建新任务。
- 历史快照支持解释当时为何这样生成，不承诺随机生成结果可以完全复现。

## 6. 共享和生命周期

### 6.1 首版权限

建议沿用当前用户体系，提供「仅自己」和「站内共享」，共享对站内所有有权登录的用户可见。共享档案默认只允许创建者及有相应管理权限的管理员维护，其他人可以使用或复制为自己的档案。

当前素材可见性判定为本人素材或审核通过的共享素材，没有在该查询中以 team_id 限定。因此，不能把现有“共享”换个名字就称为“团队可见”。真正的指定团队／客户空间作为下一阶段独立权限能力。

共享档案前展示其依赖资料：商品引用品牌时也要考虑品牌规则的可见范围。私有品牌、私有素材不能因档案分享而自动公开；缺少必要可见依赖时阻止共享，并列出需要处理的项目。若涉及素材共享审核，应沿用现有实际审核流程。

使用共享档案不会共享使用者生成的图片、会话、任务提示词或本次临时修改。公开分享图片／对话时也不默认附带完整档案内部资料。

### 6.2 更新、归档和删除

- 档案每次保存递增 revision，已创建任务保留独立快照。
- 多人或多窗口同时保存时检查 revision，提示冲突而非覆盖后保存者看到的旧值。
- 首版主推归档，可恢复；归档后不再出现在默认新建选择器，历史作品和任务仍可查看。
- 品牌归档不级联删除商品；关联商品提示品牌已归档，新任务可脱离品牌或选择替代品牌。
- 从档案移除素材仅解除关系，不直接删除素材文件；真正删除素材必须检查档案和任务快照的引用。
- 撤销共享即时影响后续读取和提交权限。已提交任务使用已合法持有的快照继续运行，后来发起的手动重试按新任务重新校验权限；已分享或已下载的成品不能被当作可自动收回。

## 7. 实现落点建议

以下是实现方向，具体字段与迁移在进入开发时确认。本轮未执行数据库修改。

### 7.1 当前可复用基础

本轮已核对当前源码与文档：

- `server/assetRoutes.ts`、`server/utils.ts`：素材上传、复用、共享审核与可见性检查。
- `src/components/chat/ChatComposer.tsx`、`src/lib/chatRequest.ts`：素材选择、表单草稿、引用整理和历史引用恢复。
- `src/types.ts`：`PromptTemplate`、`PromptTemplateResult` 已有模板与表单快照的概念。
- `docs/database-schema.md`：`image_jobs` 有请求快照，`images` 有任务关系和编辑父图关系，可作为关联基础。
- 当前工作区已有图片对比相关代码；本轮未重新验证其运行效果。
- `server/schema.ts` 中的 `branding_assets`／`branding_settings` 属于工作台自身品牌外观配置，应与业务品牌档案分开。

### 7.2 数据职责

建议业务记录放在 `app.db`，不放到渠道配置中，也不新增 `studio_settings` 使用。

| 拟新增对象 | 职责 |
| --- | --- |
| brands | 品牌文字资料、视觉规则、所有者、可见范围、revision、归档状态 |
| products | 商品基本资料、可选 brand_id、默认规格、所有者、可见范围、revision |
| product_variants | 规格属性和覆盖字段，关联 product_id |
| profile_asset_links | 档案与素材的关系、角色、规格、顺序、默认引用、使用说明 |
| image_job_profile_context | 每个任务实际使用的品牌／商品／规格身份与不可变快照 |

图片通过 job_id 查询档案上下文；为了商品作品分页查询，应对用户、商品、任务建立合适索引。若以后支持手动将旧图片归入商品，再增加独立作品关联，区分“当时用了该档案”和“后来归档到该商品”。

素材可复用现有文件，但历史任务所需的引用内容要被文件清理逻辑识别。仅保存一个可能失效的 URL 不足以支持可靠重试；需沿用并扩展现有安全文件引用／保留机制。

### 7.3 生成链路

新增统一的档案解析与上下文组装层，顺序为：权限验证 → 版本／规格校验 → 解析有效规则与素材 → 冻结快照 → 创建任务 → 沿用现有渠道调用。

CPA、ChatGPT Web、API 继续使用现有路由策略；每条链路获得相同含义的档案上下文，附件格式按原适配器转换。新能力不改变 auto 的尝试顺序。

Web 首版接入生成和继续编辑。MCP 后续开放档案搜索、详情和引用时必须复用同一组装层，不能由 MCP 客户端自行拼一套不同规则。首版未扩展 MCP 参数前，不声称 MCP 已支持档案。

### 7.4 性能原则

- 列表按游标分页，只返回卡片摘要和缩略图；进入详情才读完整规则与素材。
- 提交只处理用户选中的参考图，不遍历整个档案库或下载全部原图。
- 一般提交由确定性代码组装上下文，不额外调用 AI；智能提取或冲突检查作为显式操作。
- 档案详情与权限分开缓存处理；更新 revision 和撤销共享时失效，提交时重新校验权限。

## 8. 分期建议

| 阶段 | 交付范围 | 用户可得到的价值 |
| --- | --- | --- |
| P0：档案能用于日常创作 | 品牌／商品建档、轻量规格、素材角色、私有／站内共享、会话选择、要求预览、生成与续改接入、任务快照、我的相关作品、归档 | 每次只需补充本次创作需求，之后能按商品找回结果 |
| P1：录入更省事、复用更方便 | AI 辅助提取并逐项确认、提示词表单字段自动映射、旧作品手动关联、筛选搜索完善、MCP 档案接入 | 降低建档成本，已有内容更容易复用 |
| P2：扩展团队生产流程 | 真正按团队／客户授权、多商品组合、成套出图方案、规则版本比较、确定性文字与 Logo 排版 | 支撑复杂协作与可交付成品制作 |

P0 内部建议按“档案与素材关系 → 对话生成快照 → 续改与作品追溯 → 共享和归档验收”的顺序开发。首版完成整个流程后再扩展智能能力。

## 9. 首版验收标准

1. 建好一个品牌和两个商品后，可以多次发起创作，无需重复上传或复制品牌说明。
2. 只用品牌、商品无品牌、商品多个颜色规格三个场景都能正确带入要求。
3. 更换规格不会引用另一颜色的默认图；手动增加的素材不会被不知情地清空。
4. 用户能看见实际选择的档案、规则和参考图角色；不支持的渠道请求不会静默丢资料。
5. 修改或归档档案后，旧任务的快照、失败重试和相关作品追溯仍可解释。
6. 共享档案不泄露私有依赖和他人作品，复制／引用／撤销共享均检查权限。
